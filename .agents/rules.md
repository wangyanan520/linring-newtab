# 协作规则

## 消息与上下文

1. 所有消息、注释与报告使用中文。
2. root 派发任务时，消息必须包含：任务包编号与目标、文件白名单、禁止修改清单
   （黑名单）、验收标准、报告格式。
3. 任务消息必须独立完整：执行 agent 不得依赖"父上下文"或对话历史推断自己的任务，
   也不得把用户级指令（如"安排子 agent"）当作自己的职责——编排只属于 root。
4. 执行 agent 只响应自己收到的任务消息；收到歧义或超出范围的要求时，在报告中
   说明，不自行扩大范围。

## 文件领地

1. 每个任务包有明确文件白名单；并行组合的文件交集必须为空。
2. 工作区中已有的未提交改动（无论来自哪个任务包）必须保留，禁止 `git checkout`、
   `git reset` 等回退操作。
3. 禁止跨文件越界修改；确需调整白名单外文件时，报告 root 由 root 协调。

## 禁止事项

- 执行 agent 禁止创建子 agent；agent 间禁止互相 spawn。
- 执行 agent 禁止执行编排类动作（合并分支、派发、批次决策）。
- 禁止并行修改同一文件；文件交集非空时必须串行。
- 禁止在无验证证据的情况下声称"完成 / 已通过 / 已修复"（证据本身的有效性要求见
  「验证有效性」一节）。
- 禁止破坏性命令（`rm -rf`、`git reset --hard` 等），除非用户明确要求。

## 验证有效性

"有验证证据"不等于"证据有效"。以下三类失效在本项目历史上都真实发生过，
且**失效时一切看起来都正常**——测试是绿的、断言是过的：

1. **断言没有区分度**：新增的回归断言必须在**被测代码回退后变红**，否则不算数。
   做法：临时恢复被测文件到修复前版本（`git show <修复前提交>:<路径> > <路径>`），
   确认该断言失败，再恢复修复版。
   *案例*：E2E `[17]` 初版直接 reload 而未清节假日缓存，请求根本没发出，回退代码后
   测试依然全绿；补齐 `localStorage.removeItem('holidayCacheV1')` 后才具备区分度。

2. **验证条件与生产不符**：必须匹配生产的关键维度——存储后端（`chrome.storage`
   vs `localStorage`）、事件类型（真实点击 vs 合成 `click()`）、运行环境（扩展 vs
   预览模式）。同一段代码在不同组合下行为可能**相反**。
   *案例*：编辑表单重复 ID（P0-1）在 `chrome.storage` + 真实点击下静默写错数据，
   在 `localStorage` 下却因第二个监听器抛错中断而数据无损——只覆盖后者的 CI
   永远不会发现它。

3. **测试替身的时序不匹配**：mock / shim 必须复刻真实依赖的异步特征。例如模拟
   `chrome.storage` 必须用宏任务（`setTimeout`）而非微任务（`Promise.resolve()`），
   否则第一个监听器的续体会抢在第二个监听器之前跑完（销毁 DOM），时序类缺陷无法复现，
   测试退化为"永远通过的绿灯"。改动测试替身的异步实现前，先跑一次回退验证。

**对时序 / 异步敏感的行为必须做条件矩阵**（各维度组合逐一验证），不得用单点观察下结论。

**报告中必须区分三类陈述**：代码事实（可直接引用）、单点观察（须标注验证条件）、
普遍结论（须条件矩阵支撑）。

## 冲突处理

- 两个任务包需要修改同一文件：串行化（一个完成后，root 审查合并，再放行下一个）。
- 产物冲突：以 root 审查后的版本为准，冲突区域由 root 协调，禁止互相覆盖。
- 执行 agent 发现前置任务（依赖包）产物缺失或不完整：停止并报告 root，不自行补
  做前置任务。
