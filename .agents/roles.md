# 角色与职责

## ROOT（编排者，1 个）

- 唯一调度者：接收用户目标，拆分任务包，创建执行 agent，收集结果，执行验收。
- 维护批次与并发：同一批并行 agent 数量受限（按当前并发槽位），文件交集为空的
  任务包才能并行。
- 验收与放行：每个任务包完成后按验收标准逐条核验，通过后提交或放行下一批。
- 冲突仲裁：工作区产物冲突、文件领地被越界时，由 root 协调解决。
- 禁止：把编排职责（派发、批次决策、验收）下放给执行 agent。

## EXEC（执行 agent，每个任务包 1 个）

- 独立负责一个任务包（如 PKG-01），只修改任务说明中白名单声明的文件。
- 收到任务后先阅读 `docs/process/task-allocation.md` 对应小节，再开始工作。
- 完成后报告：改动摘要、验收标准逐条核验结果（附证据）、遗留问题。
- 禁止：
  - 创建、派生或委派任何子 agent（只有 root 可以 spawn）；
  - 执行"编排类"动作（合并分支、派发任务、批次决策、整体验收）；
  - 修改任务包之外的文件，或回退其他任务包的未提交产物。

## REVIEW（审查 agent，可选）

- 由 root 在放行前按需创建，对任务包产物做独立代码审查。
- 关注点：验收标准是否满足、是否越界改动、是否引入回归、代码质量。
- 审查结论回传给 root，不直接修改代码（除非 root 明确授权修复）。

## 用户

- 目标提供者与最终验收人；不参与 agent 间消息，执行链路上只与 root 交互。
