# 多 Agent 协作规范

本文档定义凌睿科技导航页项目中多个 AI agent 协作时的角色、规则与流程，适用于
root（编排者）分派执行 agent 完成 V3 MVP 任务包的场景。

## 文档结构

| 文件 | 内容 |
|------|------|
| `roles.md` | 角色与职责 |
| `rules.md` | 协作规则（消息、文件领地、禁止事项、**验证有效性**、冲突处理） |
| `workflow.md` | 标准工作流程（拆分、派发、验收、完成） |
| `skills.md` | 技能规范（角色 → 技能映射、技能使用规则） |

## 配套文档

- 根目录 `AGENTS.md`：项目全局规则入口，所有 agent 进入仓库后优先读取（含当前状态、
  常用命令、目录结构）
- `docs/项目评估报告.md`：独立评估结论与修复进展，接手任务前可先了解已知问题与已修项
- `docs/product/task-allocation.md`：V3 MVP 任务包定义（PKG-01~05，已全部完成），
  作为历史记录与回归清单保留

## 核心原则

1. **单点编排**：只有 root 可以创建、中断 agent 和调整批次；执行 agent 不得派生。
2. **任务原子化**：每个执行 agent 只负责一个任务包，任务消息独立完整，不依赖对话
   历史中的上下文。
3. **文件隔离**：并行任务包的文件交集必须为空；否则必须串行。
4. **证据先行**：验收必须附可复现的验证证据，禁止无证据声称完成。
   **且证据本身须先被验证有效**——断言要有区分度（回退被测代码应红灯）、验证条件要
   匹配生产环境、测试替身的异步时序要匹配真实依赖。详见 `rules.md`「验证有效性」。
