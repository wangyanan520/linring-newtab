## PBI-01 统一排序数据结构

**Why**：书签、分类、组件目前各自维护顺序逻辑，拖拽排序需要一套统一的 sortOrder 语义，否则排序功能难以扩展且容易产生数据不一致。

**What**：在 storage.js 中统一书签/分类/分类内链接/组件的排序字段语义（sortOrder 整数、排序稳定），提供通用的"重排序"存储 API；数据读取统一按 sortOrder 排序。对应 F-01（US-03）。

**Acceptance Criteria**：
- 所有列表读取按 sortOrder 升序返回，平级元素顺序稳定。
- 提供 `reorder(items, fromIndex, toIndex)` 纯函数，单测覆盖首/尾/中间移动。
- 存量数据无 sortOrder 时按原顺序补值，不丢数据。
- 排序写入后刷新页面顺序保持。

**优先级**：P0 | **工作量**：M | **依赖**：无

## PBI-02 书签拖拽排序

**Why**：效率用户希望高频书签在最前面，拖拽是最直觉的排序方式，也是竞品标配。

**What**：主页快捷书签支持鼠标拖拽换位，拖拽中有视觉反馈（半透明/占位），松开后调用 reorder 并持久化；同时提供键盘"上移/下移"替代操作。对应 F-01（US-01）。

**Acceptance Criteria**：
- 按住书签可拖动，拖拽过程有明确视觉反馈。
- 松开后顺序立即保存，刷新后保持。
- 首尾边界拖拽不丢书签、不越界。
- 键盘用户可用上移/下移按钮完成排序。
- 50+ 书签时拖拽无卡顿。

**优先级**：P0 | **工作量**：M | **依赖**：PBI-01

## PBI-03 分类拖拽排序

**Why**：与书签同理，用户需要把常用分类放最前；分类排序应与其子链接数据保持完整。

**What**：主页分类卡片支持拖拽换位，持久化；分类内链接随分类移动，数据不丢失；空分类也可排序。对应 F-01（US-02）。

**Acceptance Criteria**：
- 分类卡片可拖拽换位，位置实时生效并保存。
- 分类内链接随分类移动，数据不丢失。
- 空分类可排序。
- 刷新/重启扩展后顺序保持。

**优先级**：P0 | **工作量**：S | **依赖**：PBI-01

## PBI-04 组件注册机制

**Why**：主页区块目前写死在 index.html，无法开关与扩展；组件注册表让"搜索/书签/分类/待办/天气/农历/壁纸"成为可管理单元，是组件化改造的地基。

**What**：在 main.js 中引入轻量组件注册表（id/标题/渲染函数/默认可见），主页区块改为按注册表渲染；不引入框架。对应 F-02（US-05）。

**Acceptance Criteria**：
- 每个区块有唯一组件 id，注册表可枚举全部组件。
- 渲染入口统一走注册表，删除注册项后对应区块不渲染。
- 现有 7 个区块全部迁移完成，视觉无回归。
- 未注册组件不产生报错。

**优先级**：P0 | **工作量**：M | **依赖**：无

## PBI-05 组件显示开关与顺序调整

**Why**：极简用户希望关闭不用的区块（如天气/待办），让主页"不吵闹"；顺序调整让布局更贴合个人习惯。

**What**：设置面板新增"组件"配置：每个组件可开关，可调整顺序；设置持久化到 storage，主页按配置渲染。顺序拖拽可先做上移/下移按钮。对应 F-02（US-04/US-06）。

**Acceptance Criteria**：
- 组件开关状态保存，刷新后保持。
- 关闭组件后主页对应区块隐藏，不影响其他区块。
- 组件顺序调整即时生效并持久化。
- 全部关闭时主页仍保留搜索框（搜索为常驻组件）。

**优先级**：P0（开关）/ P1（顺序调整） | **工作量**：M | **依赖**：PBI-04

## PBI-06 导出 JSON 备份

**Why**：隐私用户不接受云同步，但需要换机/换浏览器时保留数据；导出本地 JSON 是零成本、零信任成本的备份方案。

**What**：设置面板新增"数据"区块：一键导出包含 bookmarks/categories/settings/todos 与 schemaVersion 的 JSON 文件（含文件名时间戳）。对应 F-03（US-07）。

**Acceptance Criteria**：
- 导出文件包含全部数据项与 schemaVersion。
- 导出文件名含日期（如 lingrui-nav-backup-2026-08-17.json）。
- 空数据（无书签/无待办）也能正常导出。
- 导出不触发任何网络请求。

**优先级**：P0 | **工作量**：S | **依赖**：无

## PBI-07 导入 JSON 恢复

**Why**：导出只有配合导入才有意义；导入必须安全——失败不破坏现有数据。

**What**：设置面板支持选择 JSON 文件导入：先校验格式与版本，导入前自动备份当前数据，成功后写入 storage 并刷新主页；失败给出具体错误且保持原数据不变。对应 F-03（US-08）。

**Acceptance Criteria**：
- 合法备份文件导入后，书签/分类/设置/待办完整还原。
- 非 JSON / 结构缺失 / 类型错误文件给出明确错误提示。
- 导入失败后现有数据完整不变。
- 导入成功提示包含还原的数据统计（书签数/分类数/待办数）。
- 导入后主页立即刷新为新数据。

**优先级**：P0 | **工作量**：M | **依赖**：PBI-06

## PBI-08 数据迁移兼容

**Why**：导入的文件可能来自旧版本（无 schemaVersion 或无 sortOrder），需要向前兼容，避免"备份无法恢复"。

**What**：storage 增加 schemaVersion；导入/初始化时执行版本迁移函数（v0→v1：补 sortOrder、默认组件可见性）。对应 F-03（US-09）。

**Acceptance Criteria**：
- 旧版备份（无 schemaVersion）导入后自动补默认值并升级。
- 迁移过程幂等：重复导入同文件结果一致。
- 未知高版本文件提示"文件版本高于当前版本"。

**优先级**：P1 | **工作量**：M | **依赖**：PBI-07

**Why**：代码中已有 theme 字段但未实现；深浅主题是"视觉可切换"的基本诉求，也是竞品标配。

**What**：设置面板新增主题选项（浅色/深色），通过 `data-theme` 属性 + CSS 变量切换；两套变量覆盖背景、文字、玻璃卡片、边框；即时生效并持久化。对应 F-04（US-10）。

**Acceptance Criteria**：
- 切换即时生效，无需刷新。
- 深色/浅色下所有组件（搜索/书签/分类/待办/天气/农历/设置面板）可读性正常。
- 选择持久化，重开扩展后保持。
- 无变量遗漏导致的文字不可见。

**优先级**：P0 | **工作量**：M | **依赖**：无

## PBI-10 主题与壁纸联动

**Why**：壁纸自适应取色已有基础，主题应与壁纸联动（深色壁纸配深色主题、浅色壁纸配浅色主题或手动覆盖），视觉更统一。

**What**：主题选项增加"跟随壁纸"模式：根据当前壁纸 colors 的明度自动选择深/浅主题，手动选择优先。对应 F-04（US-11）。

**Acceptance Criteria**：
- "跟随壁纸"模式下切换壁纸会自动切换主题明度。
- 手动选择主题后不随壁纸变化，除非切回跟随模式。
- 切换过程无闪烁/无白屏。

**优先级**：P1 | **工作量**：S | **依赖**：PBI-09

## PBI-11 节假日倒计时与农历信息增强

- 农历/节气显示与 lunar.min.js 数据一致。
- 无节假日数据时不显示倒计时，不报错。

**优先级**：P1 | **工作量**：M | **依赖**：无

## PBI-12 节假日数据双源容错

**Why**：节假日数据依赖外部 CDN，单一数据源故障会导致浮层缺失；双源（jsdelivr + raw.githubusercontent）已实现一半，需补缓存与重试可靠性。

**What**：节假日加载失败时展示本地兜底表（已有 2026 表）并标记数据日期；加载成功更新缓存；两源均失败时明确降级。对应 F-05（US-14）。

**Acceptance Criteria**：
- 主源失败自动切换备源。
- 两源失败时使用内置兜底表，页面无报错。
- 缓存 24h 内不重复请求。

**优先级**：P1 | **工作量**：S | **依赖**：无

**Acceptance Criteria**：
- 设置面板可见"隐私与数据"入口。
- 页面列出扩展全部权限及用途。
- 内容静态展示，不请求任何网络。

**优先级**：P1 | **工作量**：S | **依赖**：无

**优先级**：P2 | **工作量**：M | **依赖**：PBI-15

## PBI-15 核心逻辑自动化测试

**Why**：存储、排序、导入校验都是纯逻辑，出错会直接丢用户数据；自动化测试是工程化地基。

**What**：用 Node 内置 test runner 建立最小测试工程（无构建），覆盖 Storage 读写/合并、reorder、导入校验与迁移、URL 规范化等纯函数。对应 F-07（US-17）。

**Acceptance Criteria**：
- `npm test`（或等价的 node --test）可一键运行。
- 核心纯函数覆盖率 ≥ 80%。
- 测试不依赖浏览器环境（jsdom 可选）。
- 可在 CI 或本地重复执行，结果稳定。

**优先级**：P1 | **工作量**：L | **依赖**：无

## PBI-16 可复现打包

**Why**：目前 zip 手动打包且曾与源码不一致（manifest 权限缺失）；可复现打包保证发布物与源码一致。

**What**：提供打包脚本（从 src/ 生成干净 zip，排除 .DS_Store/__MACOSX），打包前跑测试与冒烟清单；产出物校验（文件数/哈希）。对应 F-07（US-18）。

**Acceptance Criteria**：
- 一条命令生成分发包。
- 包内无 .DS_Store/__MACOSX 垃圾。
- 包内容与源码目录 diff 为空。

**优先级**：P2 | **工作量**：S | **依赖**：PBI-15

## PBI-17 Firefox/Edge 兼容与网页预览

**Why**：MV3 是跨浏览器标准，适配 Firefox/Edge 可低成本扩大用户面；网页预览模式保证未装扩展也能用。

**What**：核对 API 差异（browser vs chrome、storage 兼容层已有）、manifest 兼容字段；在 Firefox/Edge 手动冒烟；网页预览模式保持现有降级路径。对应 F-08（US-19/US-20）。

**Acceptance Criteria**：
- 扩展在 Firefox/Edge 可加载且核心功能可用。
- 直接打开 index.html（无扩展环境）功能不白屏。
- 兼容性调整不破坏 Chrome 端。

**优先级**：P2 | **工作量**：L | **依赖**：PBI-04

## PBI-18 天气优雅降级与搜索快捷键

**Why**：天气 API 偶发失败，降级体验直接影响日常使用；搜索快捷键提升效率用户的操作速度。

**What**：天气失败时展示缓存/离线占位并支持手动重试（US-21）；主页面支持 `/` 聚焦搜索框、Esc 清空等快捷键（US-22）。对应 F-09。

**Acceptance Criteria**：
- 天气 API 失败时显示降级文案与重试按钮，页面无报错。
- 有缓存时展示缓存数据并标注时间。
- `/` 键聚焦搜索框，Esc 清空并失焦。
- 快捷键在输入框聚焦时不冲突。

**优先级**：P1（天气降级）/ P2（快捷键） | **工作量**：S | **依赖**：无
