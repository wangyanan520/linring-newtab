# 用户故事（User Stories）

> 文档状态：v1 初稿 · 归属：凌睿科技导航页 · 关联：01-用户画像.md（P1-P4）、05-PRD.md
> 格式：遵循 3C（Card / Conversation / Confirmation）与 INVEST（Independent, Negotiable, Valuable, Estimable, Small, Testable）
> 优先级：P0 = MVP 必须，P1 = 发布后尽快，P2 = 远期/按需

## 一、书签与分类拖拽排序

### US-01 书签拖拽排序

**标题**：书签拖拽排序

**描述**：作为 P1 效率用户，我想把常用书签拖到靠前位置，以便我每天打开主页时用最少点击到达高频网站。

**优先级**：P0

**验收标准（AC）**：
1. 鼠标按住书签可拖动，拖拽过程中有明确的视觉反馈（半透明/占位符）。
2. 松开后书签落到目标位置，顺序立即保存并持久化（刷新后不变）。
3. 设置面板与主页面的书签顺序一致。
4. 拖拽到列表首尾边界不会越界或丢失书签。
5. 键盘用户可用替代操作（如"上移/下移"按钮）完成排序。
6. 性能：50+ 书签时拖拽无卡顿（无明显延迟）。

### US-02 分类拖拽排序

**标题**：分类拖拽排序

**描述**：作为 P1 效率用户，我想调整分类区块的显示顺序，以便把最常用的分类放在最显眼位置。

**优先级**：P0

**验收标准（AC）**：
1. 分类卡片可拖拽换位，位置变化实时生效并保存。
2. 分类内书签随分类移动，数据不丢失。
3. 空分类也可排序。
4. 顺序持久化，刷新/重启扩展后保持。

### US-03 书签排序与分类关联（工程性故事）

**标题**：统一排序数据结构

**描述**：作为开发者（P4），我想让书签与分类共用一套稳定的排序机制（如 sortOrder 字段 + 变更事件），以便拖拽、按钮排序和未来的组件化都能复用同一逻辑。

**优先级**：P0（工程前置）

**验收标准（AC）**：
1. Storage 层提供 `reorder` 类 API，原子更新顺序且不产生竞态。
2. 主页面与设置面板订阅同一数据源，一处变更两处同步。
3. 现有 add/update/delete API 行为不变（无回归）。
4. 数据迁移：已有旧数据（无 sortOrder）自动补齐，不丢书签。

## 二、组件化改造

### US-04 组件开关

**标题**：组件显示开关

**描述**：作为 P3 极简审美者，我想在设置里开关时钟/天气/待办/农历日历等组件，以便页面只保留我需要的部分。

**优先级**：P0

**验收标准（AC）**：
1. 每个组件有独立开关，关闭后主页面立即隐藏该区块，不影响其他组件。
2. 开关状态持久化，刷新后保持。
3. 全部组件关闭时页面有兜底提示（如仅保留搜索框），不出现空白异常。
4. 组件开关与壁纸/主题等全局设置互不干扰。

### US-05 组件注册机制（工程性故事）

**标题**：组件注册与渲染解耦

**描述**：作为开发者（P4），我想把写死在 index.html 的区块改为"组件注册表 + 动态渲染"，以便未来新增组件（如纪念日、热搜）时不动主页面结构。

**优先级**：P0（工程前置）

**验收标准（AC）**：
1. 新增组件只需在注册表中声明（id/渲染函数/默认开关），无需修改 index.html 主体结构。
2. 组件渲染失败（如天气接口超时）不影响其他组件与搜索框。
3. 每个组件可独立加载/卸载，卸载后无残留事件监听（无内存泄漏）。
4. 现有组件（时钟/天气/待办/日历/书签/分类）全部迁移到注册表后，视觉与行为无回归。

### US-06 组件顺序调整

**标题**：组件排序（可选增强）

**描述**：作为 P3 用户，我想调整组件区块的上下顺序，以便按自己的使用习惯布局页面。

**优先级**：P1

**验收标准（AC）**：
1. 设置面板中可上下调整组件顺序，主页面实时反映。
2. 顺序持久化。
3. 与组件开关共用同一配置界面，操作路径不冲突。

## 三、数据导入导出

### US-07 导出配置

**标题**：导出 JSON 备份

**描述**：作为 P1 隐私用户，我想把书签、分类、待办和设置一键导出为 JSON 文件，以便换设备或重装浏览器时保留我的配置。

**优先级**：P0

**验收标准（AC）**：
1. 设置页"导出"按钮生成包含全部用户数据的 JSON 文件并触发下载。
2. 文件包含版本号与导出时间，结构可读（含字段说明或注释）。
3. 导出内容不含任何浏览器未授权的数据（仅书签/分类/待办/设置）。
4. 导出失败（如无权限）时给出明确错误提示。

### US-08 导入配置

**标题**：导入 JSON 恢复

**描述**：作为 P1 隐私用户，我想从 JSON 文件恢复我的配置，以便在新环境快速还原。

**优先级**：P0

**验收标准（AC）**：
1. 支持选择 JSON 文件导入，导入前校验格式与版本。
2. 校验失败（损坏/版本不兼容）时提示原因，且不破坏现有数据。
3. 导入为字段级合并：备份中含有的字段覆盖现有数据，备份中缺失的字段保留现有数据（兼容旧备份）；导入前自动备份现有数据，校验失败或写入失败不修改现有数据。
4. 导入完成后主页面立即刷新为新数据。
5. 导入的书签 URL 做安全校验（仅 http/https/chrome-extension 协议，防 XSS；chrome-extension 用于书签指向扩展自身页面）。

### US-09 数据迁移兼容（工程性故事）

**标题**：旧数据兼容迁移

**描述**：作为开发者（P4），我想在数据层加入版本化迁移机制，以便未来数据结构变更时旧配置仍可导入。

**优先级**：P1

**验收标准（AC）**：
1. 数据文件带 schema 版本号，导入时自动执行迁移脚本。
2. 无法迁移的字段丢弃但不影响其余数据导入。
3. 迁移逻辑有单测覆盖。

## 四、主题切换

### US-10 深色/浅色主题

**标题**：深浅主题切换

**描述**：作为 P3 审美用户，我想在浅色与深色主题间切换，以便夜间使用不刺眼。

**优先级**：P0

**验收标准（AC）**：
1. 设置中提供浅色/深色两档，切换后全页面（含设置面板）立即生效。
2. 深色主题下所有文本、图标、玻璃卡片对比度满足 WCAG AA（正文 ≥ 4.5:1）。
3. 主题状态持久化，重开扩展后保持。
4. 壁纸较亮时深色主题仍可读（取色逻辑与主题联动）。
5. 农历浮层、天气弹层、待办等所有子界面无遗漏。
6. （后续迭代，非 MVP）跟随系统/跟随壁纸档位见 PBI-10，不进本期验收。

### US-11 主题与壁纸联动

**标题**：主题与壁纸自动协调

**描述**：作为 P3 用户，我想让页面文字颜色跟随壁纸亮度自动调整，以便任何壁纸下都清晰可读。

**优先级**：P1

**验收标准（AC）**：
1. 换壁纸时自动检测主色/亮度，调整文字与卡片对比度。
2. 手动主题优先于自动推断（用户手动选择后不覆盖）。
3. 深色壁纸下默认进入深色表现，亮色壁纸反之。

## 五、农历与节假日强化

### US-12 节假日倒计时

**标题**：节假日倒计时提醒

**描述**：作为 P2 农历用户，我想在主页看到下一个节假日还有几天，以便提前安排出行和调休。

**优先级**：P1

**验收标准（AC）**：
1. 日期浮层中展示下一个法定节假日名称与剩余天数（如"端午还有 5 天"）。
2. 数据源不可用（如 holiday-cn 拉取失败）时使用内置兜底表，不显示错误。
3. 节假日前 7 天自动展示，过后自动切换为下一个节假日。
4. 调休上班日有明确标识（如红色标注"班"）。

### US-13 农历信息增强

**标题**：农历信息卡片

**描述**：作为 P2 用户，我想在主页时间附近直接看到今日农历与节气，以便不用点开浮层就能获取关键信息。

**优先级**：P1

**验收标准（AC）**：
1. 顶部时间下方展示"农历日期 + 当日节气/节日"（如"六月初七 · 立秋"）。
2. 无特殊节气/节日时只显示农历日期，不出现空占位。
3. 显示内容与浮层日历一致（同一数据源）。
4. 组件可关闭（遵循组件开关）。

### US-14 节假日数据源容错

**标题**：节假日数据双源容错

**描述**：作为开发者（P4），我想让节假日数据具备"在线拉取 + 本地兜底"双源机制，以便断网时功能仍可用。

**优先级**：P1（工程）

**验收标准（AC）**：
1. 在线数据拉取成功时缓存，失败时自动回退本地内置表。
2. 本地表按年份维护，缺少年份给出明确"数据未更新"提示而非错误。
3. 数据更新不阻塞页面渲染（异步加载）。

## 六、隐私纯净加固

### US-15 权限与隐私展示

**标题**：隐私可见化

**描述**：作为 P1 隐私用户，我想在设置页看到"本扩展收集什么/不收集什么"的清晰说明，以便放心使用。

**优先级**：P1

**验收标准（AC）**：
1. 设置页新增"隐私"区块，列出权限清单（如"仅 storage，用于本地保存书签/设置"）。
2. 明确声明：无广告、无统计埋点、无第三方请求（除用户主动使用的天气/壁纸/节假日数据源）。
3. 所有外部数据源在文档中列出并可一键查看（wttr.in / Bing 壁纸 cn.bing.com、bing.biturl.top / 节假日 cdn.jsdelivr.net、raw.githubusercontent.com / favicon.im）。
4. 文案无歧义、无"默认收集"类条款。

### US-16 无埋点回归防护（工程性故事）

**标题**：网络请求审计

**描述**：作为开发者（P4），我想让代码中所有网络请求集中声明、可审计，以便任何新增请求都必须经过显式注册。

**优先级**：P2（工程）

**验收标准（AC）**：
1. 新增网络请求需在统一模块注册（URL + 用途 + 触发条件）。
2. 测试或 CI 检查可枚举全部请求域名，防止悄悄加埋点。
3. manifest 的 host_permissions 与注册表一致。

## 七、工程化基础

### US-17 核心逻辑自动化测试

**标题**：数据层与工具函数测试

**描述**：作为开发者（P4），我想为 Storage、排序、导入导出校验等核心逻辑建立自动化测试，以便重构时有回归保障。

**优先级**：P1（工程）

**验收标准（AC）**：
1. 引入轻量测试运行器（如 Node 内置 test runner 或 Vitest），不引入重型框架。
2. 覆盖：add/update/delete/reorder、导入校验、迁移、escapeHtml 等工具函数。
3. `npm test`（或等价命令）可一键运行，CI 中自动执行。
4. 现有行为（无测试的旧逻辑）不因补测试而改变。

### US-18 构建与分发物一致性

**标题**：可复现打包

**描述**：作为开发者（P4），我想用一条命令从源码生成可加载的扩展包（含 zip），以便保证分发物与源码一致。

**优先级**：P2（工程）

**验收标准（AC）**：
1. 提供打包脚本（如 `npm run pack`）生成干净 zip（无 __MACOSX / .DS_Store）。
2. 打包产物与源码 manifest 一致（含完整 host_permissions）。
3. 打包脚本可重复执行，产物可校验（哈希）。

## 八、跨浏览器适配（远期）

### US-19 Firefox / Edge 兼容

**标题**：跨浏览器可用

**描述**：作为 P4 极客用户，我想在 Firefox 和 Edge 中安装同一套扩展，以便不被 Chrome 生态绑定。

**优先级**：P2（远期）

**验收标准（AC）**：
1. 代码中无 Chrome-only API（或使用 polyfill 封装 `chrome.*` / `browser.*`）。
2. 在 Firefox（MV3 支持版本）与 Edge 中加载扩展，核心功能（书签/搜索/天气/待办/日历）无回归。
3. 不在商店上架，通过"开发者模式加载"或自签分发可用。

### US-20 网页预览模式保持

**标题**：网页直开模式兼容

**描述**：作为开发者（P4），我想让页面在普通浏览器直接打开时也能预览（storage 降级 localStorage），以便开发调试无需打包。

**优先级**：P1

**验收标准（AC）**：
1. 直接打开 index.html 时功能可用（localStorage 持久化）。
2. 降级模式与扩展模式数据互不串扰（不同 key 或明确标识）。
3. 新增功能（组件化/导入导出）在两种模式下行为一致。

## 九、现有功能体验增强

### US-21 天气失败降级

**标题**：天气组件优雅降级

**描述**：作为 P1 用户，我想在天气服务不可用时看到明确但温和的提示，以便知道是网络问题而不是扩展坏了。

**优先级**：P1

**验收标准（AC）**：
1. 请求失败/超时 5 秒内显示"天气暂不可用"+ 重试入口。
2. 失败不影响其他组件加载。
3. 成功恢复后自动刷新，无需手动重载页面。

### US-22 搜索增强

**标题**：搜索历史与快捷键

**描述**：作为 P1 效率用户，我想用键盘快捷键快速聚焦搜索框并记住上次引擎，以便减少鼠标操作。

**优先级**：P2

**验收标准（AC）**：
1. 按 `/` 或 `Ctrl/Cmd+K` 聚焦搜索框。
2. 记住上次使用的搜索引擎（持久化）。
3. 与现有引擎循环切换不冲突。
