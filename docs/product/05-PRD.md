## 1. Summary

本 PRD 定义"凌睿科技导航页"V3 的升级范围：在不引入云同步、AI、移动端和商店上架的前提下，围绕"可组装、可备份、可切换、可测试"四个目标，补齐拖拽排序、数据导入导出、主题切换、组件化改造、农历强化与工程化基础。V3 的定位不变：隐私纯净、轻量、免费、面向中文用户的新标签页。

## 3. Background

### 3.1 现状

凌睿科技导航页是 Manifest V3 Chrome 扩展，原生 HTML/CSS/JS，无构建工具、无测试。现有功能完整可用：多引擎搜索、快捷书签 CRUD、分类导航 CRUD、待办、天气（wttr.in）、农历日历（节假日/调休/干支）、壁纸（3 预设 + Bing 每日 + 随机）、设置面板。数据存储于 chrome.storage.local（localStorage 回退）。

### 3.2 为什么是现在

2026-08 竞品调研显示（Tabliss/nightTab/Bonjourr 等开源项目与 Infinity/iTab/WeTab/Momentum 对比）：

- 头部产品（Infinity、iTab、WeTab）的核心卖点是**可组装布局与小组件生态**，本项目目前是固定布局。
- 头部产品普遍支持**数据同步/备份**；本项目纯本地，用户换设备即丢失配置，导入导出是最低成本补齐方案。
- 2025-12 社区曝光"Infinity 投毒"事件后，隐私纯净成为强需求；本项目仅申请 storage 权限，是天然优势，但需要**把隐私承诺变成可见功能**。
- 头部开源项目全部有**自动化测试与 CI**，本项目无测试、手动打包，工程化落后。

### 3.3 约束

- 明确不做：Chrome 商店上架、AI 组件、移动端/网页版、云同步。
- 技术约束：MV3、原生 JS、无构建工具；新增能力不得引入重型依赖；保持页面首屏性能。

## 4. Objective

### 4.1 目标

把凌睿科技导航页从"功能完整但不可组装"升级为"高可定制、数据可备份、视觉可切换、代码可测试"的隐私纯净型新标签页，同时为后续多浏览器分发打好工程基础。

### 4.2 关键结果（SMART）

| 编号 | 关键结果 | 度量方式 | 目标值 |
|------|----------|----------|--------|
| KR-1 | 用户可自定义主页结构 | 组件开关可用且设置持久化 | 100% 配置刷新后保留 |
| KR-2 | 用户可备份/恢复数据 | 导出 JSON 可重新导入并完整还原 | 往返还原率 100% |
| KR-3 | 用户可切换深/浅主题 | 主题切换入口可用且生效 | 2 种主题可即时切换 |
| KR-4 | 代码可测试 | 核心逻辑（存储/排序/导入校验）单测覆盖率 | ≥ 80% |
| KR-5 | 无功能回归 | 现有功能自动化冒烟测试通过率 | 100% |
| KR-6 | 隐私承诺可见 | 设置页展示权限清单 | 1 处入口、无埋点 |

## 6. Value Proposition(s)

### 6.1 用户收益

- **数据自己掌控**：一键导出/导入 JSON，换浏览器、换电脑可完整迁移，不依赖任何账号。
- **主页自己组装**：组件可开关、可排序，书签可拖拽，深浅主题可切换。
- **信息本土化**：农历、节气、节假日、调休倒计时，是国际产品没有的差异化能力。
- **隐私不妥协**：仅 storage 权限、零埋点、零广告，设置页明示权限与数据去向。

## 7. Solution

### 7.1 UX / 用户流程

核心交互流程见 03-用户用例与用户流程.md（UC-03~UC-11），端到端体验见 04-用户旅程地图.md。V3 新增入口：

- 设置 → 通用：主题切换（深/浅/跟随壁纸）。
- 设置 → 数据：导出备份、导入恢复（含格式校验与冲突提示）。
- 设置 → 组件：组件列表开关与顺序调整。
- 主页面：书签/分类卡片拖拽排序；组件隐藏时对应区块消失。

|----------|------|----------|--------|------|

### 7.3 技术方案

- **存储层**：保持 chrome.storage.local + localStorage 回退；新增 `schemaVersion` 字段，导入时按版本迁移。
- **排序**：书签/分类/组件统一使用 `sortOrder` 字段（已有基础），拖拽修改后批量写回存储。
- **组件化**：轻量注册表（`COMPONENTS` 数组 + 渲染函数映射），不引入框架；组件显隐由设置项控制。
- **主题**：`data-theme` 属性 + CSS 变量切换，深/浅两套变量，壁纸取色继续用现有 `--accent-*` 体系。
- **导入导出**：JSON Schema 校验（手工实现轻量校验函数），导入前备份当前数据，失败可回滚。
- **测试**：Node 内置 `node:test` 或最小测试框架，覆盖 Storage 与导入/排序纯逻辑；页面渲染用冒烟脚本。

### 7.4 Assumptions（假设）

- 用户主要使用 Chrome 桌面端；Firefox/Edge 兼容为远期，不阻塞 V3 MVP。
- 用户接受"本地备份代替云同步"；不要求多设备自动同步。
- 组件化采用"开关+排序"而非完整拖拽布局，满足多数定制需求且成本可控。
- 现有 wttr.in / Bing 壁纸 / jsdelivr 节假日源保持可用；均有降级预案。
- 无运营资源，V3 不包含数据分析、埋点、推送等需要服务端的能力。
