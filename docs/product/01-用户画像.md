# 用户画像（Personas）

> 文档状态：v1 初稿 · 归属：凌睿科技导航页 · 用途：作为用户故事、PRD、路线图的决策依据
> 方法：基于 2026-08-13 竞品调研（Tabliss / nightTab / Bonjourr / Infinity Pro / WeTab / iTab / Momentum）、V2 设计文档与现有源码分析归纳。当前阶段为**假设驱动的画像**，尚未经过真实用户访谈验证，详见"数据缺口"章节。

---

## 画像总览

| # | 画像 | 一句话 | 核心动机 |
|---|------|--------|----------|
| P1 | 隐私逃离者 · 效率白领 | "我只是想要一个干净的起始页，不想被当成流量。" | 隐私安全 > 功能多 |
| P2 | 农历依赖者 · 中文家庭用户 | "打开浏览器第一眼就知道今天什么日子。" | 中国式信息（农历/节假日）顺手可得 |
| P3 | 极简审美者 · 设计与学生用户 | "好看、不吵，我才愿意每天打开。" | 视觉舒适 + 轻量不打扰 |
| P4 | 折腾型极客 · 开源爱好者 | "我要自己掌控一切，最好还能改。" | 可定制性 + 本地可控 |

## P1 隐私逃离者 · 效率白领

**人口特征**：28-40 岁，互联网/金融/行政等行业白领或开发者，Chrome 重度用户（每天打开 50+ 次新标签页），工作中依赖书签和快速搜索。

**关键特征**：关注国产新标签页（Infinity / WeTab）的广告位、内容流和"顺便帮你优化"的默认行为；关注过 2025-12 社区曝光的"新标签页投毒"事件（上传浏览历史、键盘记录、劫持返利链接等指控）。

**主要 Job-to-be-Done（JTBD）**：每天无数次回到浏览器首页时，用最少的点击找到常用网站、发起搜索，同时**不交出任何数据**。频率：每天 30-100 次。

**Top 3 痛点**
1. 商业新标签页默认带信息流/广告，设置项多且默认值偏"数据收集"（严重）。
2. 担心被追踪：不知道扩展到底上传了什么（严重）。
3. 想换开源方案但配置成本高，或者没有农历/天气这类本地化功能（中等）。

**Top 3 期望收益**
1. 一眼可见的隐私承诺：权限最少、无埋点、本地存储。
2. 数据自己掌控：可导出 JSON 备份，换设备可恢复。
3. 日常效率不降级：书签、搜索、天气、待办都够用。

**一个意外洞察**：这类用户对"少而透明的权限"的信任感，比"功能强大"更能驱动安装与留存；他们愿意为隐私放弃 80% 的额外功能，但**不能**接受放弃书签同步的替代方案——所以离线导出/导入必须做得极其顺手。

**产品契合度**：本项目天然契合（仅 storage 权限、零埋点、本地存储）。风险点：没有云同步意味着换机成本高，必须用一键导入导出补足；需要把隐私承诺可视化（如设置页展示权限清单）。

## P2 农历依赖者 · 中文家庭用户

**人口特征**：30-50 岁，中文母语，工作与生活需要农历信息（节气、节日、宜忌、调休），不是技术用户，不愿意研究设置项，手机和电脑都用但浏览器是主力入口。

**关键特征**：习惯"打开浏览器顺便看一眼今天农历几号、什么时候放假"；对天气预报敏感（通勤/接送孩子）；对广告反感但不主动抗争。

**主要 JTBD**：打开浏览器时，一眼获得"今天是几号、农历几月几、是否放假/调休、天气如何"。频率：每天 2-5 次，节假日前夕频次上升。

**Top 3 痛点**
1. 主流新标签页（含国外产品）几乎没有农历/节假日调休信息（严重）。
2. 查日历要专门开 App 或搜索，多一步操作（中等）。
3. 配置复杂的功能看不懂，害怕误操作把主页弄乱（中等）。

**Top 3 期望收益**
1. 农历 + 节假日 + 调休信息默认就显示，无需配置。
2. 重要节日前有提醒（如"下周一端午"）。
3. 界面不用动，开箱即用。

**一个意外洞察**：这类用户对"今天的日子"的记忆锚点是**农历和放假安排**而非公历；在节假日前后，这个需求会超越其他所有功能，成为他们打开主页的唯一理由。

**产品契合度**：本项目独有优势（农历日历浮层 + 节假日调休），必须持续强化并做成本页面的记忆点。风险点：信息密度要克制，不能做成"日历 App"抢走浏览器首页的简洁感。

## P3 极简审美者 · 设计与学生用户

**人口特征**：20-30 岁，设计/传媒从业者或在校学生，对 UI 质感敏感，喜欢玻璃拟态、渐变壁纸、夜间模式；见过大量"好看但没用"的起始页，留存取决于第一眼的视觉感受。

**关键特征**：会截图分享好看的起始页到社交平台；偏好浅色/深色跟随系统；讨厌开屏广告和内容流；愿意为了"好看 + 轻"牺牲部分功能。

**主要 JTBD**：每天打开浏览器时获得视觉愉悦，且页面不打扰工作流。频率：每天 10-30 次（视使用强度）。

**Top 3 痛点**
1. 壁纸无法自定义上传，只能从预设/自动壁纸里选（中等）。
2. 缺少深色模式，深夜使用刺眼（中等）。
3. 组件（时钟/天气/待办/日历）不能按自己喜好增减，布局固定（中等）。

**Top 3 期望收益**
1. 深色/浅色主题一键切换（或跟随系统）。
2. 自定义壁纸上传 + 自动取色。
3. 组件可开关，保持"该有的有、不该有的不出现"。

**一个意外洞察**：对这类用户，**空状态和细节动效**比功能多少更能决定去留；"壁纸 + 主题 + 组件开关"三件套的完成度，是复购（留存）的核心。

**产品契合度**：V2 玻璃拟态设计已具备基础，缺主题切换与组件化。风险点：深色主题不是简单反色，需要重新设计取色与透明度方案，否则会破坏现有玻璃质感。

## P4 折腾型极客 · 开源爱好者

**人口特征**：25-40 岁，开发者/运维/安全从业者，会读源码、会提 issue，喜欢"自己掌控一切"；愿意花时间配置，但厌恶闭源黑盒。

**关键特征**：会因为"权限列表干净 + 无埋点 + 可本地运行"而选择项目；会在 GitHub/V2EX 上讨论和传播；对响应速度、无网络依赖的功能稳定性敏感。

**主要 JTBD**：获得一个可审计、可离线、可控的新标签页，必要时自己改代码。频率：配置期高频，之后日常使用。

**Top 3 痛点**
1. 无法导出/导入配置，换机要重配（严重）。
2. 没有自动化测试，改代码没有安全感（中等）。
3. 布局固定，想调整结构只能改 HTML（中等）。

**Top 3 期望收益**
1. 配置数据是纯 JSON，可读、可改、可迁移。
2. 有基础测试，社区贡献者有信心。
3. 组件/布局层面可扩展（哪怕是通过配置）。

**一个意外洞察**：这类用户是"免费口碑引擎"——他们的转发能让项目在开发者社区冷启动，但他们也是最容易因"不透明"而流失的群体：任何一次不明所以的网络请求都会失去他们的信任。

**产品契合度**：本地优先 + 纯 JSON 数据模型天然匹配。风险点：目前无测试、无构建、全局脚本架构，需要轻量工程化补强（不引入重型框架，保持"打开即用"的简单）。

## 画像优先级与数据缺口

**优先级排序（产品决策按此加权）**：
P1 隐私逃离者 > P2 农历依赖者 > P3 极简审美者 > P4 折腾型极客

理由：P1 是当前市场空窗的最大人群（有明确痛点 + 付费/传播意愿），P2 是差异化功能的核心受众，P3 决定留存与口碑，P4 决定社区冷启动。

**数据缺口（后续需验证的假设）**：
1. 隐私敏感人群的规模与付费/捐赠意愿（未量化）。
2. 农历/节假日功能的真实使用频次（需要埋点，但当前产品无埋点——建议用**可选且明示**的方式调研，如设置页"参与匿名统计"开关）。
3. 拖拽排序 vs 按钮排序的偏好（当前竞品均支持拖拽，但目标用户对鼠标拖拽的熟悉度未知）。
4. 深色主题的实际需求强度（P3 画像基于竞品共性推断）。
