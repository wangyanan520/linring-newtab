## 1. P0：会直接误导操作

### P0-1 版本号三处打架，发布入口写错

`AGENTS.md:114` 写"当前版本：**1.2.0**"，而 `src/manifest.json:4` 是 `1.2.6`，`CHANGELOG.md:19` 最新节也是 `[1.2.6]`。

风险是具体的：全局规则 5 要求"对外分发前递增 version"，照 `AGENTS.md` 从 1.2.0 递增会得到 **1.2.1**，而 `CHANGELOG.md:197` 已有 `[1.2.1]` 一节。版本号重复会被 Chrome Web Store 拒绝。

同类漂移：`package.json:3` 仍是 `1.2.0`，`package-lock.json:3,9` 更落后到 `1.1.0`。`tools/pack.js:185-186,207` 只读 manifest，故**不影响打包产物**；CI 也不读该字段。属于元数据问题，但会让 `npm version` 从错误的基线递增。

**建议**：`AGENTS.md:114` 改 1.2.6；若需表达"最后已发布版本"，必须显式区分"已发布 x / 工作区 y"。`package.json` 同步，或删除该字段并声明只以 manifest 为准。

### P0-2 `.agents/rules.md` 说"三类失效"，实际有四类

`.agents/rules.md:31`：「以下**三类**失效在本项目历史上都真实发生过」，但该节现有 4 个编号条目（断言无区分度 / 验证条件不符生产 / 替身时序不匹配 / 静态检查≠语义正确）。

这是**本次审查前一轮改动引入的**——第 4 类是为记录 `transition: all` 翻车案例新增的，总数表述没跟着改。`AGENTS.md` 全局规则 3 把这一节当作证据有效性的唯一标准，读者会漏掉第 4 类。

**建议**：改为"以下四类"。注意 `.agents/rules.md:62` 的"三类陈述"（代码事实 / 单点观察 / 普遍结论）确实是 3 类，**不要一并改**。

### P0-3 "15 项全部落地"与同文"3 项未完成"直接冲突

`docs/product/10-使用体验优化方案.md:3` 写"v2 已实施（15 项全部落地）"，`AGENTS.md:23` 也写"15 项（UX-01~15）全部落地"，但同一份方案的 `§9.4`（:822-830）明确列了三项未完成：

1. UX-12 的"右键/长按菜单"未做
2. UX-15 的"Esc 关闭设置面板"（原本已有，未新增）
3. 扩展模式的真实权限弹窗未人工验证

更矛盾的是 `AGENTS.md:27` 自己就写着"未完成项与原因见方案 §9.4"——同一段落里先宣称全部落地、再指向未完成清单。

**建议**：改为"15 项主体落地，3 项增强/验证项见 §9.4"，或补做后再宣称完成。
